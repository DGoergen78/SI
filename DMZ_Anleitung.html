Eine DMZ im Cisco Packet Tracer aufbauen

Vom leeren Netzwerk bis zum geschützten Webserver — Schritt für Schritt, mit Befehlen, Erklärungen und Selbsttests.

Ca. 90–150 Minuten · Partnerarbeit möglich
0 von 17 Aufgaben erledigt

Warum brauchen wir eine DMZ?

Die Muster GmbH möchte ihre Webseite von außen erreichbar machen. Der Webserver soll aber nicht im gleichen Netz wie die Büro-PCs stehen: Wird er angegriffen, sollen Angreifer nicht direkt ins interne Netz gelangen.

Merksatz: Die DMZ ist ein eigenes Netz zwischen Internet und internem LAN. Ein Router kontrolliert den Verkehr zwischen den Zonen.

Unser Netzwerk auf einen Blick

Vereinfacht: In den beiden unteren Netzen hängen die Endgeräte jeweils an einem Switch (SW-LAN bzw. SW-DMZ). Der externe PC ist über R2 erreichbar.

Mini-Wissenstest

Warum kommt der öffentlich erreichbare Webserver in die DMZ?

Schritt 1: Netzwerk bauen

Öffne Cisco Packet Tracer. Wir verwenden dieselben Adressen und Geräte wie im Arbeitsauftrag, aber arbeiten in überschaubaren Schritten.

R1 = Firmenrouter, R2 = simuliertes Internet

2× Switch 2960

SW-LAN und SW-DMZ

3× PC

1× Server

SRV-WEB mit HTTP-Dienst

Die Adressen 203.0.113.x und 198.51.100.x sind reservierte Dokumentationsnetze; hier simulieren sie das Internet.

Was bedeutet „Standardgateway“?

Das ist die IP-Adresse des Routers im eigenen Netz. Ein PC schickt Pakete an andere Netze dorthin. Für PC-LAN1 ist das 192.168.10.1.

Schritt 2: Router startklar machen

Jetzt bekommen die Router ihre Schnittstellenadressen. Öffne jeweils Router → CLI und füge die Befehle ein. Falls der Einrichtungsdialog erscheint, antworte mit no.

R1 — Firmenrouter

R1 verbindet LAN, DMZ und externes Netz. no shutdown aktiviert die jeweilige Schnittstelle.

enable
configure terminal
hostname R1
interface gigabitEthernet0/0
 description LAN
 ip address 192.168.10.1 255.255.255.0
 no shutdown
exit
interface gigabitEthernet0/1
 description DMZ
 ip address 172.16.0.1 255.255.255.0
 no shutdown
exit
interface gigabitEthernet0/2
 description EXTERN
 ip address 203.0.113.2 255.255.255.248
 no shutdown
exit
ip route 0.0.0.0 0.0.0.0 203.0.113.1
end
write memory
Standardroute: „Wenn ich das Zielnetz nicht kenne, schicke ich das Paket an R2 (203.0.113.1).“

R2 — unser simuliertes Internet

enable
configure terminal
hostname R2
interface gigabitEthernet0/0
 ip address 203.0.113.1 255.255.255.248
 no shutdown
exit
interface gigabitEthernet0/1
 ip address 198.51.100.1 255.255.255.0
 no shutdown
exit
end
write memory

Für die Veröffentlichung der Webserver-Adresse 203.0.113.3 reicht das direkt angeschlossene externe Netz. R2 hat bewusst keine Route zum privaten LAN.

Hilfe: Was tun, wenn ein Interface „administratively down“ ist?

Gehe in das betreffende Interface und gib no shutdown ein. Prüfe danach die Verkabelung. Hinweis: Die Portnamen hängen vom Routermodell ab — hier wird ein Cisco 2911 vorausgesetzt.

Schritt 3: NAT — Adressen übersetzen

PAT für das LAN

Mehrere Büro-PCs gehen nach außen über eine öffentliche Routeradresse: 203.0.113.2. PAT unterscheidet die Verbindungen u. a. anhand der Ports.

Statisches NAT für den Server

Unser Server 172.16.0.10 bekommt nach außen die feste Adresse 203.0.113.3. Besucher kennen nur die äußere Adresse.

NAT-Befehle auf R1

enable
configure terminal
interface gigabitEthernet0/0
 ip nat inside
exit
interface gigabitEthernet0/1
 ip nat inside
exit
interface gigabitEthernet0/2
 ip nat outside
exit
access-list 10 permit 192.168.10.0 0.0.0.255
ip nat inside source list 10 interface gigabitEthernet0/2 overload
ip nat inside source static 172.16.0.10 203.0.113.3
end
write memory

Einfach erklärt: inside bezeichnet die privaten Seiten, outside die externe Seite. overload aktiviert PAT.

Was bedeutet 0.0.0.255 in der NAT-ACL?

Das ist eine Wildcard-Maske. Sie steht hier für das gesamte Netz 192.168.10.0/24. Sie ist nicht dasselbe wie die Subnetzmaske 255.255.255.0.

Schritt 4: ACLs — der Türsteher

Mit Access Control Lists (ACLs) bestimmen wir, wer mit wem sprechen darf. Das sind Filterregeln am Router, keine vollständige zustandsbehaftete Firewall.

Unser vereinfachtes Regelwerk

VonNachRegel
InternetWebserver✅ HTTP, HTTPS, Ping
InternetLAN⛔ verboten
LANWebserver✅ HTTP, HTTPS, Ping
LANRestliche DMZ⛔ verboten
LANInternet✅ erlaubt
DMZLAN/Internet⛔ keine neuen Verbindungen
Wichtig: ACL-Regeln werden von oben nach unten geprüft. Die erste passende Regel entscheidet. Am Ende steht unsichtbar ein deny ip any any.

1. Zugriff von außen kontrollieren

Diese ACL kommt an R1 auf Gi0/2 in — der Verkehr kommt dort von außen in den Router.

enable
configure terminal
ip access-list extended EXTERN_IN
 remark Externe Zugriffe auf den Webserver
 permit tcp any host 203.0.113.3 eq 80
 permit tcp any host 203.0.113.3 eq 443
 permit icmp any host 203.0.113.3 echo
 remark Rueckverkehr aus dem LAN
 permit tcp any any established
 permit icmp any any echo-reply
 deny ip any any log
exit
interface gigabitEthernet0/2
 ip access-group EXTERN_IN in
exit
end

HTTP = TCP 80, HTTPS = TCP 443. Bei eingehendem Verkehr wird hier die öffentliche Serveradresse verwendet (wie in der Vorlage).

2. LAN kontrollieren

enable
configure terminal
ip access-list extended LAN_IN
 remark Zugriff auf Webserver
 permit tcp 192.168.10.0 0.0.0.255 host 172.16.0.10 eq 80
 permit tcp 192.168.10.0 0.0.0.255 host 172.16.0.10 eq 443
 permit icmp 192.168.10.0 0.0.0.255 host 172.16.0.10 echo
 remark Rest der DMZ sperren
 deny ip 192.168.10.0 0.0.0.255 172.16.0.0 0.0.0.255
 remark LAN darf ins Internet
 permit ip 192.168.10.0 0.0.0.255 any
exit
interface gigabitEthernet0/0
 ip access-group LAN_IN in
exit
end

Die Ausnahme für den Webserver steht vor dem Verbot für die restliche DMZ.

3. DMZ kontrollieren

enable
configure terminal
ip access-list extended DMZ_IN
 remark Nur bestimmte Antworten zuruecklassen
 permit tcp 172.16.0.0 0.0.0.255 any established
 permit icmp 172.16.0.0 0.0.0.255 any echo-reply
 deny ip any any log
exit
interface gigabitEthernet0/1
 ip access-group DMZ_IN in
exit
end
write memory

Neue Zugriffe vom Server aus werden blockiert. Rückantworten für einfache TCP- und Ping-Tests werden zugelassen.

Mini-Wissenstest

Was bedeutet ip access-group LAN_IN in an Gi0/0?

Praxisgrenze: established prüft nur bestimmte TCP-Flags und ersetzt keine Stateful Firewall. Auch HTTP/HTTPS-Rückpakete oder NAT-/ACL-Verhalten können im Simulator je nach Gerät/Version Besonderheiten zeigen. Dies ist ein Lernlabor, keine sichere Produktionskonfiguration.

Trage nach jedem Versuch das tatsächliche Ergebnis ein. Die Einträge werden in diesem Browser lokal gespeichert.

Wenn etwas nicht funktioniert …

1. Verbindung scheitert schon zum Gateway

IP-Adresse, Maske, Gateway, Kabel und show ip interface brief prüfen. Router-Ports müssen „up/up“ sein.

2. Internet klappt nicht

Auf R1 die Standardroute (show ip route) und NAT prüfen (show ip nat translations). Teste zuerst den externen PC direkt über R2.

3. Website nicht erreichbar

Am Server HTTP unter Services aktivieren. Prüfe die öffentliche NAT-Adresse und die Trefferzähler in show access-lists. Eine falsch positionierte ACL-Regel kann den Zugriff blockieren.

4. Zugriffe werden unerwartet erlaubt

Prüfe, ob die ACL am richtigen Interface in der richtigen Richtung aktiv ist: show running-config.

Abschlussfrage

Warum ist diese Packet-Tracer-ACL-Konfiguration noch keine vollwertige Firewall?

Geschafft! Du hast LAN, DMZ und Internet getrennt, NAT eingesetzt, ACLs konfiguriert und das Ergebnis geprüft.
